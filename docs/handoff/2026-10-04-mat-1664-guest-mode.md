# Task: Account-less Local mode (Guest), account created at first Cloud use (MAT-1664)

**Date:** 2026-10-04 · **Repo:** SnipNote · **Branch:** main (work in a worktree, see below)

## What to do
Implement Linear **MAT-1664**. Today `AuthenticationView` is the app root and shows a login screen until the user signs in. Make Local mode work as a **Guest** with no Account: a fresh install goes straight to onboarding and recording, Guests write nothing to Supabase (apart from anonymous analytics), and an **Account** (email + password, the existing flow) is created the first time the user enters Cloud mode. Creating the Account grants the one-time 30-minute **Trial grant** and then pushes the Guest's local meetings before any pull. Start by reading the code and bringing Mattia a short design (where the Cloud entry points are, how "continue the action" works), then build it. The Linear issue's acceptance criteria are authoritative.

## Context you need
- ADR 0001 (`docs/adr/0001-local-mode-free-and-accountless.md`) and `GLOSSARY.md` fix the decisions and vocabulary. Don't reopen them: Local mode is free forever and never needs an Account; email at Cloud entry, **not** anonymous Supabase users (rejected: balance lost on reinstall, repeat Trial grants); new installs default to Local mode (done in MAT-1659); Pro is an Account with a positive Minutes balance.
- MAT-1658 (done) already made sync safe for this: `MeetingSyncService.syncFromServer` pushes local-only meetings before the first pull and never deletes a local meeting because the server lacks it. The first account to sync on a device claims the local meetings (`sync.localMeetingsOwnerId`). Consequence to confirm with Mattia: a returning user who reinstalls as a Guest and then signs in to their old account will push the Guest meetings into that account.
- Local mode must stay free: no Minutes, no paywall, no sign-in prompt anywhere on a Local path.
- Analytics (`SnipNote/AnalyticsService.swift`) already works with no session and sends nothing before onboarding completes. Keep it that way, and send no account ID or email in any event.
- **Overlap with MAT-1670** (another agent, in the main checkout): it is locking down database functions callable by `anon`, possibly including ones the app calls for the Trial grant (for example `grant_free_tier_minutes`, `handle_new_user_signup`, `credit_minutes`). Do not change database permissions here. First find how the Trial grant works today (client-side `freeTierGranted` or a server trigger), and write down which RPCs your Cloud-entry path will call, so Mattia can reconcile it with MAT-1670.
